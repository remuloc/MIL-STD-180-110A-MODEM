# 1. FEC – Forward Error Correction

## 1.1. Overview

This module implements and validates the Forward Error Correction (FEC) stage of the MIL-STD-188-110A modem.

The main objective is to develop an independent convolutional encoder implementation in Python and verify its functional equivalence with the FEC encoder implemented in GNU Radio.

Both implementations process the same original binary input sequence. Their encoded outputs are subsequently compared bit by bit to identify possible discrepancies.

## 1.2. Validation Architecture

The validation process uses two independent implementations of the convolutional encoder:

- **GNU Radio:** Receives the original binary message and performs FEC encoding.
- **Python:** Receives the same original binary message and independently performs FEC encoding.

After both encoding operations are completed, the Python validation script reads the corresponding output files and performs a bit-by-bit comparison.

## 1.4. Encoder Parameters

The Python implementation currently uses the following parameters:

| Parameter | Value |
|---|---|
| Constraint Length (K) | 7 |
| Generator Polynomial 1 | 6 |
| Generator Polynomial 2 | 5 |
| Number of output bits | 2 |
| Coding Rate | 1/2 |
| Initial State | 0 |

The generator polynomials are represented in decimal format and used in bitwise masking and parity calculations.

**Note:** The polynomial representation, register shift convention, bit ordering, and encoder configuration must be verified against the actual GNU Radio implementation to ensure functional equivalence.

## 1.5. Binary Input Processing

The input file is read in binary mode.

The bytes are converted into individual bits using the MSB First (Most Significant Bit First) convention. Therefore, the most significant bit of each byte is processed first.

The script allows the number of processed input bits to be limited through the following parameter:

```python
LIMIT_INPUT_BITS = 4
```

When set to `None`, the entire input message is processed.

This feature allows initial tests to be performed using short binary sequences before running the complete validation.

## 1.6. Python FEC Encoding

The Python script implements the convolutional encoder using a shift register.

For each input bit:

1. The shift register is updated.
2. The new input bit is inserted into the register.
3. The corresponding generator polynomial masks are applied.
4. The parity of each encoder output is calculated.
5. The encoded bits are appended to the output sequence.

The resulting encoded sequence is stored in the `4 OUTPUT PYTHON` directory.

## 1.7. GNU Radio Output Processing

After GNU Radio completes the FEC encoding process, its output file is loaded by the Python validation script.

In the current implementation, each byte in the GNU Radio output file is expected to represent one encoded bit, with a value of either 0 or 1.

The script checks this condition before performing the comparison.

If any byte contains a value other than 0 or 1, the program raises an exception indicating an incompatible output format.

## 1.8. Bit-by-Bit Comparison

The validation script compares the encoded sequence generated by Python against the encoded sequence generated by GNU Radio.

The following parameters are evaluated:

- Number of encoded bits generated by Python.
- Number of encoded bits generated by GNU Radio.
- Number of bits compared.
- Number of matching bits.
- Number of mismatching bits.
- Exact positions of mismatching bits.

The comparison is performed up to the length of the shorter sequence.

The program also checks whether both sequences have exactly the same total length.

## 1.9. Validation Criteria

The validation is considered successful when:

1. Both encoders receive exactly the same original binary input sequence.
2. Both implementations use equivalent encoding parameters and conventions.
3. Both encoded sequences have the same length.
4. Every corresponding output bit is identical.

If discrepancies are detected, the script reports the positions of the mismatching bits and their respective values in each implementation.

## 1.10. Expected Results

The expected result is complete equivalence between the FEC encoded sequences generated by Python and GNU Radio.

This validation procedure provides an independent reference implementation of the convolutional encoder and establishes a verification baseline for the development and integration of the remaining modem processing blocks.

## 1.11. Modem Integration

The FEC module represents one of the processing stages of the MIL-STD-188-110A communication system.

Its independent implementation and validation are important to ensure the reliability of the modem's digital signal processing chain.

Once validated, the module can be integrated with the remaining modem processing stages while maintaining independent documentation, implementation, and testing procedures.
